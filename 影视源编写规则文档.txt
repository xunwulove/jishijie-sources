极视界 · 影视源编写规则文档（AI执行版）

你的任务

分析一个影视网站，判断它属于哪种类型，然后生成极视界桌面版可以导入的影视源配置。

> 版本说明：极视界 v1.4+ 已完整兼容标准 TVBox / 影视仓 type=4（XPath）规则（含 cateExclude / cateVodFlag / limit / limitR / {key} / {searchKey} / {page} 等扩展字段与占位符，详见附录B）。
> 你既可以按本文"简单格式"编写极简规则，也可以直接采用网上现成的 TVBox XPath 规则文件。
> 同时 v1.4+ 已完整兼容 drpy2 生态 type=3 爬虫源（饭太硬/肥猫等），内置 drpy2 运行时（独立线程执行，不阻塞界面），导入即用、无需自写爬虫。
> 极视界 v1.5.x 进一步优化：源管理按类型分板块（CMS / drpy / 规则）；重复源检测按类型隔离判重（type=3 按 ext 判重，其余类型按归一化 api 判重，避免不同采集子路径误判）。以上均不影响本文的源编写规则。
> v1.5.x 列表标题正则接线：cateVodNameR / homeVodNameR / searchNameR 三个字段已生效——可对列表项标题做正则二次加工（如去掉前后缀、提取纯净片名）；简化格式分类列表的 cateId 也已支持 cateIdR 正则加工。内部健壮性：type=1 CMS 请求非 2xx 自动降级重试、type=3 drpy2 脚本 fetch 兼容标准 Response 用法。

---

第一步：判断网站类型

访问网站，根据以下标准判断类型：

类型A：标准CMS源（type=1）— 最简单

判断方法：
在网站域名后拼接 /api.php/provide/vod/?ac=list，用浏览器访问。

如果返回 JSON 或 XML 数据（包含 code、list、vod_name、vod_pic 等字段），就是标准CMS源。

标准CMS源只需要一个字段：API地址。

示例：
- 网站首页：https://www.example.com
- API地址：https://www.example.com/api.php/provide/vod/

类型B：规则引擎源（type=4）— 需要解析网页

判断方法：
如果 /api.php/provide/vod/?ac=list 返回 404、HTML页面或错误信息，说明不是标准CMS，需要用规则引擎解析网页。

规则引擎需要你分析网页结构，编写 XPath 规则。极视界支持两种写法：

写法  说明  适用

**标准 TVBox 格式**（推荐）用 TVBox 生态的字段名（`cateVodNode`/`dtFromNode`/`dtUrlNode` 等），兼容网上大量现成规则几乎所有 XPath 影视站
**简化格式**         用 `searchList`/`cateList`/`detailXxx` 等简写字段，结构精简               结构简单的站


类型C：不支持

如果网站是以下类型，直接说明不支持：
- 需要登录才能观看
- 视频是加密的且没有公开解析接口
- 纯网盘分享站（没有独立的详情页）
- 纯 JS 动态渲染、源码里没有列表/详情数据的单页应用（XPath 无法解析）

类型D：drpy 爬虫源（type=3）— 复用生态脚本

判断方法：
- 网站/他人提供了含 homeContent / categoryContent / detailContent / searchContent 四个入口的 JS 爬虫脚本
- 或你希望直接复用 TVBox 生态里饭太硬、肥猫等分享的 drpy2 规则脚本（.js）

极视界 type=3 支持两类：

子类型  说明  编写难度

**drpy2 生态源**（推荐，兼容饭太硬/肥猫）`api` 指向 drpy2.min.js 运行时，`ext` 指向规则脚本（如 `电影.js`）。极视界内置完整 drpy2 运行时，直接可用，**无需自己写爬虫**极低
**自包含脚本**               单个脚本自身定义 `rule` + 四个入口函数，极视界直接执行                                            高

第二步：生成配置

类型A：标准CMS源输出格式

```json
{
  "sites": [
    {
      "key": "网站英文标识",
      "name": "源显示名称（中文）",
      "type": 1,
      "api": "https://域名/api.php/provide/vod/",
      "searchable": 1,
      "quickSearch": 1,
      "filterable": 1
    }
  ]
}
```

字段说明：
- key：唯一标识，用英文小写，如 feifan、baofeng
- name：显示名称，如 "非凡资源"
- type：固定为 1
- api：API地址，必须以 /api.php/provide/vod/ 结尾
- searchable：1=可搜索，0=不可搜索
- quickSearch：1=参与快速搜索，0=不参与
- filterable：1=首页显示分类，0=不显示

类型B：规则引擎源输出格式（type=4）

ext 的两种形态（都支持）：

1. 内联规则对象（离线可用，推荐）——把规则直接写进 ext
2. 规则文件 URL（在线拉取）——ext 填一个指向 TVBox 规则 JSON 文件的网址，极视界会自动拉取解析

形态一补充说明：请求配置（encoding / headers / ua）

上面 ext 里的 encoding 与 headers 用于控制抓取站点时的请求参数：

字段  类型  说明

`ua`      string  请求的 User-Agent。留空则用默认 PC UA
`encoding`string  页面编码：`utf-8`（默认）、`gbk`、`gb2312`。**GBK 编码的老站必须填 `gbk`**，否则中文会乱码、XPath 匹配失败
`headers` object  自定义请求头（可选）。会**合并**到请求头中，可覆盖默认 UA / Referer / 增加 Cookie 等。例：`"headers": { "Referer": "https://域名", "Cookie": "..." }`。注意 `headers` 里的 `User-Agent` 优先级高于 `ua`

类型D：drpy 爬虫源输出格式（type=3）

形态一：drpy2 生态源（推荐，兼容饭太硬/肥猫）

这是饭太硬、肥猫等分享的源格式。你不需要编写爬虫，只需引用现成的 drpy2 规则脚本（.js）。极视界内置了完整的 drpy2 运行时，导入后自动识别并执行。

```json
{
  "sites": [
    {
      "key": "csp_drpy_film",
      "name": "片库",
      "type": 3,
      "api": "https://git.xxx.com/.../drpy2.min.js",
      "ext": "https://git.xxx.com/.../电影.js",
      "searchable": 1,
      "quickSearch": 1,
      "filterable": 1
    }
  ]
}
```

字段说明：
- api：drpy2 运行时地址（通常指向 drpy2.min.js）。极视界识别到 api/jar 为 drpy2.js 运行时，且 ext 为 .js 规则脚本时，自动走内置 drpy2 运行时。
- ext：规则脚本地址，决定抓取哪个站（如 电影.js、短剧资源.js）。这是饭太硬生态里按站点/题材拆分好的规则。
- 同一个运行时（drpy2.min.js）可以配合多个不同的 ext 规则脚本，分别抓取不同站点。

形态二：自包含 drpy 脚本源

如果手头有一个自包含的 drpy 爬虫脚本（脚本自身用 var rule = {...} 定义 rule，并实现 homeContent/categoryContent/detailContent/searchContent 四个函数），把脚本内容或脚本 URL 填到 ext 即可：

```json
{
  "sites": [
    {
      "key": "csp_self_drpy",
      "name": "自写爬虫源",
      "type": 3,
      "api": "",
      "ext": "https://example.com/crawler.js",
      "searchable": 1,
      "quickSearch": 1,
      "filterable": 1
    }
  ]
}
```

> 自包含脚本的四个入口函数签名（TVBox drpy 标准）：
> - homeContent(res) → {class:[...], list:[...]}
> - categoryContent(tid, pg, fast, filter, extend) → {list:[...], page, pagecount}
> - detailContent(ids) → {list:[{vod_id, vod_name, vod_play_from, vod_play_url,...}]}
> - searchContent(wd, quick) → {list:[...]}

第三步：规则引擎详细编写指南

3.1 URL模板变量

变量  含义  用在哪里

`{wd}`                       搜索关键词                 searchUrl
`{key}` / `{searchKey}`      搜索关键词（别名，TVBox 常见写法）  searchUrl
`{pg}` / `{catePg}` / `{page}`页码（从1开始）              searchUrl, cateUrl
`{tid}` / `{cateId}` / `{typeId}`分类ID                  cateUrl
`{id}` / `{vid}`             影视ID                  dtUrl, detailUrl
`{playUrl}`                  集数播放路径                playUrl


示例：
- 搜索URL：https://example.com/index.php/ajax/suggest?mid=1&wd={wd}&limit=10（也可用 {key} / {searchKey} 占位）
- 分类URL：https://example.com/show/{cateId}--------{catePg}---2021.html
- 详情URL：https://example.com/vod/{vid}.html
- 播放页URL：https://example.com/vodplay/{playUrl}.html

> 注意：如果 cateVodId 提取的是完整URL（如 https://example.com/vod/123.html），dtUrl 里填 {vid} 时软件会直接用该完整URL，无需拼ID。
> 如果提取的是ID（如 123），dtUrl 需要写 https://example.com/vod/{vid}.html。

3.2 如何编写XPath规则

列表规则（必填）

1. 用浏览器打开网站的分类页或首页
2. 右键点击一个影片卡片 → 检查，查看HTML结构
3. 找到所有卡片的共同父元素，写 cateVodNode
4. 在每个卡片内分别提取标题、图片、ID、备注

示例HTML结构（苹果CMS stui 模板为例）：
```html
<ul class="stui-vodlist">
  <li>
    <div class="stui-vodlist__box">
      <a href="/vod/123.html" title="流浪地球" data-original="/poster/123.jpg">
        <span class="pic-text">HD</span>
      </a>
    </div>
  </li>
</ul>
```

对应规则：
```
cateVodNode: .//div[contains(@class,'stui-vodlist__box')]  或  //ul[@class='stui-vodlist']/li
cateVodName: .//a/@title
cateVodId:   .//a/@href
cateVodImg:  .//a/@data-original
cateVodMark: .//span[contains(@class,'pic-text')]/text()
```

详情与播放规则（推荐填写）

详情页通常有两级：
1. 详情页提取标题、封面、简介、播放线路和集数链接
2. 播放页（/vodplay/...）里常有一个 var player_aaaa = {"url": "https://.../index.m3u8", ...} 的JS变量，真实视频地址在里面

配置示例：
```
dtName:        //div[contains(@class,'myui-content__thumb')]/a/@title
dtImg:         //div[contains(@class,'myui-content__thumb')]/a/img/@data-original
dtFromNode:    //a[@data-toggle='tab' and contains(@href,'playlist')]
dtFromName:    /text()
dtUrlNode:     //ul[contains(@class,'myui-content__list')]
dtUrlSubNode:  li/a
dtUrlId:       @href
dtUrlIdR:      /vodplay/(\S+).html
dtUrlName:     /text()
playUrl:       https://域名/vodplay/{playUrl}.html
playRealUrl:   true     ← 关键：软件会自动抓播放页解析 player_aaaa 里的真实 m3u8/mp4
```

> playRealUrl: true 让软件对每个集数二次抓取播放页，从 var player_aaaa={...} 里提取真实视频地址。
> 如果不设此字段，软件会把详情页的集数链接当作播放地址（可能无法直接播放）。

3.3 常用XPath表达式

表达式  含义

`//div[@class='item']`           选取class为item的所有div
`.//h3`                          当前节点下的所有h3（相对路径，必须以.开头）
`/a/text()`                      a元素的文本内容
`/img/@src`                      img元素的src属性
`/a/@title`                      a元素的title属性
`//div[contains(@class,'video')]`class包含video的div
`//ul/li[1]`                     第一个li元素
`//a/@href`                      所有a元素的href属性


> 重要：在列表项内提取子元素时，XPath必须以 .// 开头（相对路径），否则会从整个文档查找。
> 极视界已修复命名空间问题，//div 这类标准 XPath 表达式可直接使用。

3.4 常用正则二次加工（xxxR 字段）

TVBox 规则里的 xxxR 字段用于对 XPath 提取的结果做正则二次加工，提取纯净内容。常见写法：

写法  作用

`/vodtype/(\w+).html`从链接里提取分类ID
`/vodplay/(\S+).html`从播放链接里提取ID
`\S+(http\S+)`       从懒加载属性里提取完整图片URL
`\S+(http\S+)`       提取真实图片地址


3.5 JSON 接口（搜索或列表返回JSON时）

如果网站的搜索/列表是 JSON 接口，用 scVodNode 等字段：

```
searchUrl: https://域名/index.php/ajax/suggest?mid=1&wd={wd}&limit=10
scVodNode: json:list     ← json: 前缀表示返回的是JSON，node是JSONPath
scVodName: name
scVodId:   id
scVodImg:  pic
```

JSONPath 写法（json: 后面跟 JSONPath 表达式，用于定位列表数组）：

写法  说明

`json:list`         顶层数组 `list`
`json:data.list[*]` `data` 下的 `list` 数组（逐级下钻）
`json:data[*].name` `data` 数组里每项的 `name`
`json:$.data.list[*]`以 `$.` 开头的完整 JSONPath（可选，等价于 `data.list[*]`）


> scVodName/scVodId/scVodImg/scVodMark 填的是数组元素内的字段名（如 name/id/pic），不是 JSONPath。若元素是嵌套对象，也可用 a.b 形式取深层字段。
> 简化格式（自研引擎）里，cateList/cateName/cateId/searchList 等若以 $. 开头也会自动按 JSONPath 处理，可用 ruleType: "jsonpath" 强制 JSON 模式。

3.6 完整实战：从零分析一个站点（Walkthrough）

下面以一个典型「苹果 CMS + stui 模板」的影视站为例，演示从拿到站点到产出可导入 type=4 配置的完整流程。这是判断你能否独立写对 XPath 的核心演练。

Step 1 — 判断类型
访问 https://example.com/api.php/provide/vod/?ac=list，返回 404 / HTML 页面（不是 JSON/XML）→ 不是 CMS 源，判定为 type=4 规则引擎源。

Step 2 — 拿列表页 HTML 分析结构
访问分类页 https://example.com/show/1--------1---2021.html，右键 → 查看网页源代码。找到影片卡片的 HTML（本例）：

```html
<div class="module-item">
  <a href="/vod/123.html" title="流浪地球2">
    <div class="module-item-cover">
      <img class="lazyload" data-original="/upload/123.jpg" />
    </div>
    <div class="module-item-text">更新至30集</div>
  </a>
</div>
```

Step 3 — 反推列表字段 XPath
- 列表项节点（所有卡片的共同父级容器）：cateVodNode = //div[@class='module-item']
- 标题：cateVodName = .//a/@title
- 详情链接：cateVodId = .//a/@href
- 封面（注意是 data-original 懒加载属性，不是 src）：cateVodImg = .//img/@data-original
- 备注：cateVodMark = .//div[@class='module-item-text']/text()

> 关键规则：卡片内部子元素 XPath 必须用 .// 开头（相对路径）；用属性用 @xxx；封面看图是不是懒加载（data-original）。

Step 4 — 拿详情页 HTML 分析播放结构
访问 https://example.com/vod/123.html，看播放线路与集数：

```html
<a class="playlist-tab" href="#playlist1">线路一</a>
<ul id="playlist1">
  <li><a href="/vodplay/123-1-1.html">第01集</a></li>
  <li><a href="/vodplay/123-1-2.html">第02集</a></li>
</ul>
```

反推详情字段：
- 详情标题：dtName = //h1/text()
- 线路名节点：dtFromNode = //a[contains(@class,'playlist-tab')]，dtFromName = text()
- 集数容器：dtUrlNode = //ul[contains(@class,'playlist')]
- 集数项：dtUrlSubNode = li/a，dtUrlId = @href，dtUrlName = text()
- 播放页模板：playUrl = https://example.com/vodplay/{playUrl}.html

Step 5 — 判断是否需要二次抓取播放页
访问 https://example.com/vodplay/123-1-1.html，源码里有 var player_aaaa={"url":"https://cdn.../index.m3u8"} → 真实地址在播放页 JS 变量里。因此要设：
- playUrl = https://example.com/vodplay/{playUrl}.html
- playRealUrl = true（软件自动抓播放页解析 player_aaaa 的真实 m3u8/mp4）

Step 6 — 组装完整可导入配置

```json
{
  "sites": [
    {
      "key": "csp_xpath_example",
      "name": "示例站",
      "type": 4,
      "api": "https://example.com",
      "searchable": 1,
      "quickSearch": 1,
      "filterable": 1,
      "ext": {
        "homeUrl": "https://example.com",
        "encoding": "utf-8",
        "cateUrl": "https://example.com/show/{cateId}--------{catePg}---2021.html",
        "cateVodNode": "//div[@class='module-item']",
        "cateVodName": ".//a/@title",
        "cateVodId": ".//a/@href",
        "cateVodImg": ".//img/@data-original",
        "cateVodMark": ".//div[@class='module-item-text']/text()",
        "dtName": "//h1/text()",
        "dtFromNode": "//a[contains(@class,'playlist-tab')]",
        "dtFromName": "text()",
        "dtUrlNode": "//ul[contains(@class,'playlist')]",
        "dtUrlSubNode": "li/a",
        "dtUrlId": "@href",
        "dtUrlName": "text()",
        "playUrl": "https://example.com/vodplay/{playUrl}.html",
        "playRealUrl": true
      }
    }
  ]
}
```

Step 7 — 导入软件实测：把这段 JSON 加入源管理（内联 ext），用下面第四步的「规则测试」验证，据报错修正。

3.7 常见失败与排错

症状  原因  排查 / 解决

**列表一直为空 / 0 条**      ① `cateVodNode` 没写对，或子字段 XPath 用了 `//` 而非 `.//`；② 站点反爬返回拦截页① 检查卡片共同父元素，子字段统一用 `.//` 开头；② 加 `headers` 模拟浏览器 / `ua`；确认 `cateUrl` 能访问到数据
**标题/图片能出，但点进详情 404** `cateVodId` 提取的是相对路径，`dtUrl` 拼接错误                      看 `cateVodId` 拿到的值：若是 `123` 用 `dtUrl = https://域名/vod/{vid}.html`；若是完整 URL（`/vod/123.html` 相对或 `http...` 绝对）则软件直接用，无需拼接
**中文全部乱码**            站点是 GBK/GB2312 编码                                      `ext` 里设 `"encoding": "gbk"`
**图片不显示（灰图/空图）**      封面在懒加载属性 `data-original` 而非 `src`                      `cateVodImg = .//img/@data-original`；若是相对路径用 `xxxImgR` 正则补全完整 URL（如 `\S+(http\S+)`）
**播放点开没画面**           集数链接指向播放页，但真实 m3u8 在播放页 JS 变量里，没开二次抓取                  设 `playUrl`（播放页模板）+ `playRealUrl = true`
**搜索返回空**             搜索接口是 JSON 但没按 JSON 写，或搜索 URL 用错占位符                    用 `scVodNode: json:xxx` + `scVodName/scVodId/scVodImg` 字段；搜索 URL 用 `{wd}` 占位符
**分类只出首页/不切分类**       `cateUrl` 模板里 `{cateId}`/`{catePg}` 占位没生效或写错           确认 URL 模板里的占位符与 `cateVodId` 传的 ID 形式匹配
**「获取列表失败 / 详情失败」**   站点被墙、改版或反爬                                             看错误信息：`HTTP 4xx/5xx` 多为反爬/失效，`PARSE` 多为返回的不是预期格式（可能改版了），加 UA/headers 或换源
**type=4 规则是 URL 但拉取失败**规则文件 URL 网络受限                                          改用「内联规则对象」（把规则 JSON 直接写进 `ext`）

第四步：验证你的输出

生成配置后，检查以下事项：

标准CMS源检查清单
- [ ] API地址是否以 /api.php/provide/vod/ 结尾？
- [ ] 用浏览器访问API地址是否返回数据？
- [ ] key是否唯一且为英文？

规则引擎源检查清单
- [ ] cateUrl（或 homeVodNode）存在，能访问到列表？
- [ ] cateVodNode 能匹配到多个列表项？
- [ ] 列表项内的XPath以 .// 开头？
- [ ] dtUrl 能正确拼接详情页？
- [ ] dtUrlNode / dtUrlSubNode 能提取到集数？
- [ ] 如果播放地址在 /vodplay/ 页，是否设置了 playUrl + playRealUrl: true？
- [ ] 图片URL是完整地址？(相对路径可用 xxxImgR 正则补全)
- [ ] type=4 源的 ext 是有效JSON（内联）或指向规则文件的URL？

drpy 爬虫源检查清单（type=3）
- [ ] type 固定为 3？
- [ ] drpy2 生态源：api 指向 drpy2.min.js 运行时，ext 指向 .js 规则脚本？
- [ ] 自包含脚本源：ext 指向含 rule + 四个入口函数的脚本？
- [ ] key 唯一且为英文？

用软件实测验证（闭环，最重要）

生成的配置不要只看"结构对"，一定要导入软件实测，据真实反馈修正：

1. 添加源：在「设置 → 影视源」点添加，填入 type 与 ext（type=4 内联规则 / type=3 的 api+ext）。
2. 规则测试：type=4 添加后点「规则测试」，软件会拉列表 + 详情 + 播放地址，返回"可用 / 获取列表失败 / 详情失败"等结论与错误信息。
3. 检查全部：对已添加的源点「检查全部」，可批量验证所有源能否拉到列表。
4. 据报错修正：
   - 获取列表失败: HTTP 4xx/5xx → 反爬 / 失效，加 UA/headers 或换源
   - 获取列表失败: PARSE 响应不是有效的 JSON 或 XML → 站点改版或类型判错
   - 规则可用但未获取到数据 → 列表 XPath 没匹配上，回 Step 3 修正 cateVodNode 及子字段
   - 列表有数据但播放失败 → 检查 playUrl/playRealUrl，看是否需要二次抓取播放页
5. 播放实测：点进一部影视，确认能出剧集、能播放、图片正常，才算真正合格。

> 一个"能通过规则测试、能拉到列表与详情、能出播放地址"的源才是合格源。遇到失败用 3.7 排错表逐条对照。

附录B：标准 TVBOX 规则文件参考字段

TVBox / 影视仓生态的 XPath 规则文件（通常带 // 注释，不是标准JSON）常用字段与极视界对应关系：

TVBox原字段  极视界支持  说明

`homeUrl`                                                                 ✅  网站首页，用于补全相对URL
`ua`                                                                      ✅  请求UA（留空用默认 PC UA）
`headers`                                                                 ✅  自定义请求头对象（合并到请求头，可覆盖 UA/Referer/Cookie 等）
`encoding`                                                                ✅  页面编码 `utf-8`/`gbk`/`gb2312`（GBK 老站必填 `gbk`）
`cateNode`/`cateName`/`cateId`/`cateIdR`                                  ✅  分类导航
`cateExclude`                                                             ✅  分类排除（命中该 XPath 的分类节点被过滤掉）
`cateManual`                                                              ✅  手动指定分类
`homeVodNode` 系列                                                          ✅  首页列表（`homeVodNameR` 标题正则）
`cateVodNode` 系列                                                          ✅  分类列表（`cateVodNameR` 标题正则）
`cateVodFlag`                                                             ✅  列表项标记过滤（仅保留含指定标记的项，如 VIP/付费标识）
`limit` / `limitR`                                                        ✅  列表条数限制（数字，或正则从文本提取）
`dtUrl`/`dtName`/`dtImg`/`dtDesc`/`dtCate`/`dtYear`/`dtArea`/`dtMark`/`dtActor`/`dtDirector`✅  详情字段（均支持对应 `dtXxxR` 正则二次加工）
`dtFromNode`/`dtFromName`                                                 ✅  播放线路
`dtUrlNode`/`dtUrlSubNode`/`dtUrlId`/`dtUrlIdR`/`dtUrlName`               ✅  集数列
`playUrl`                                                                 ✅  播放页模板
`searchUrl`/`scVodNode`(json:)/`scVodName`/`scVodId`/`scVodIdR`/`scVodImg`/`scVodMark`✅  搜索（JSON/HTML 均可）
`searchNameR`                                                             ✅  搜索列表标题正则二次加工
`{key}`/`{searchKey}`/`{page}` 等 URL 占位符                                  ✅  搜索关键词与页码别名
`xxxR` 正则字段                                                               ✅  二次加工（含列表标题 `cateVodNameR`/`homeVodNameR`/`searchNameR`、简化分类 `cateIdR`）


可以直接把网上的 TVBox XPath 规则文件内容放入 ext（内联）即可使用。
